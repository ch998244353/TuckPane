# 稳定性问题：本地诊断与用户手测

本次修复针对源码中可证实的风险。其他电脑反馈的卡死、闪退、拖入或打开失败尚无现场复现，不能仅凭定向检查通过认定全部解决。

## 出现问题后

1. 记下发生时间、最后一步操作，以及程序是否仍在托盘/任务管理器中。不要反复强制触发故障。
2. 程序能操作时，打开 **设置 → 系统 → 本地诊断 → 导出诊断包**，选择保存 ZIP 的位置。
3. 程序已经退出时，可由你正常重新启动后导出。日志轮转有容量上限，尽量在故障后尽快导出。
4. 自行决定是否把 ZIP 和现象说明分享给开发者。应用不自动上传。

导出取消不报错；目录权限或磁盘故障会显示失败提示，原有目标文件不会在诊断包生成前被覆盖。可选的 Windows 应用错误事件无法读取时，其他内容仍会导出。

## 诊断包内容

- `runtime.jsonl`：新格式的白名单运行记录，包括会话、构建 MVID、操作标识、阶段、数量、耗时、错误分类和 HResult。历史记录在导出时再次校验、重新序列化。
- `environment.json`：应用/.NET/Windows版本、进程架构、丢弃/写入失败计数，以及可读取的最近 Windows 应用错误事件摘要。
- `README.txt`：取证能力和解释边界。

新日志位于应用选用的本地数据根目录下的 `diagnostics`，包括兼容旧 GlassFolder 根目录的情况；最多 4 个文件，每个 5 MiB。正常日志后台写入，队列有界，写入失败或拥塞不阻塞界面。

不收集文件正文、便签内容、文件名、完整路径、原始启动参数、异常自由文本、状态配置或内存转储。旧 `TuckPane.log` 不删除，也不进入新诊断包；旧 `collect-lifecycle-diagnostics.ps1` 只供旧版历史记录使用，不是本轮默认导出路径。

记录缺失不能单独证明正常退出或崩溃。原生 fail-fast、强制结束、电源中断和磁盘故障可能没有最后记录。Shell 请求完成仅表示系统接受调用，不能证明外部软件显示了窗口。开始后缺少结束记录仅代表最后观察到的阶段，不是根因证明。

## 本轮手测清单

由用户自行启动应用并验证，agent 不操作电脑、鼠标键盘或窗口：

- 常用文件、文件夹、应用 `.lnk`、Steam `.url` 拖入及点击打开；包含中文与空格路径。
- 拖入失败或取消后，窗口仍可交互，再次拖入可用；已有复制/移动习惯保持。
- 传输未结束时退出：等待超时后程序保留并提示，安全结束后可再次退出。
- 外部修改收纳目录后内容刷新；删除/导出异常后原本打开的便签与待办仍可操作。
- 导出诊断包、取消导出和换一个可写目录重试。

非 GUI 自动验证只使用 `TuckPane.LogicChecks --stability <area>` 的本轮精确 area。禁止无参数、历史全量和真实鼠标/窗口测试脚本。实际已执行的命令与结果以根目录 `PLAN.md` 为准。
