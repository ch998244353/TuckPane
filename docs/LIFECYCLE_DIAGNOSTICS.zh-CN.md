# 本地异常诊断与用户手测

TuckPane 4.1.0 只记录失败、超时、意外中断及可获取的崩溃信息。正常运行、成功操作、主动取消和正常退出不记录；本次不增加正常操作轨迹、卡顿监控或内存转储。

## 出现问题后

1. 记下发生时间、时区、最后一步操作，以及程序是否仍在托盘或任务管理器中。
2. 程序能操作时，打开 **设置 → 系统 → 本地诊断 → 导出诊断包**，选择保存 ZIP 的位置。已经退出时，可正常重新启动后导出。
3. 尽量在故障后尽快导出，以免旧记录因本地容量限制被轮转淘汰。包内时间统一为 UTC；北京时间需在 UTC 上加 8 小时。
4. 自行决定是否把 ZIP 和现象说明分享给开发者。应用不自动上传。

导出取消不报错。目录权限或磁盘故障会显示失败提示；临时归档生成、关闭并通过大小验证后才替换目标，失败或取消保留原目标并清理本次临时文件。

## 容量与包内内容

- ZIP 硬上限 **5 MiB（5,242,880 字节）**。`runtime.jsonl` 最多使用 4 MiB UTF-8 内容预算；辅助文件合计最多 256 KiB，其余留给 ZIP 开销。
- `runtime.jsonl`：重新校验、过滤后的异常记录。超出预算时保留时间最新的完整记录，按时间顺序输出。
- `environment.json`：应用、.NET、Windows 版本与架构，导出时间、保留范围与记录计数、容量省略计数、采集状态，以及可读取的 Windows 应用错误摘要。
- `README.txt`：记录范围、容量、采集状态的解释及分享说明。

日志位于应用实际选用的数据根目录下的 `diagnostics`，兼容旧 GlassFolder 数据根。最多 4 个文件，每个最多 5 MiB，总计 20 MiB。异常记录通过有界队列后台写入；正常记录在入队前过滤，不计入队列丢弃数。写入失败或拥塞不阻塞界面。

历史 JSON 日志不清空，随既有轮转自然淘汰；导出时再次执行异常过滤和字段白名单。旧格式缺失的新增信息不猜测补全。旧自由文本 `TuckPane.log` 不删除，也不进入诊断包；旧 `collect-lifecycle-diagnostics.ps1` 仅供旧版历史记录使用。

## 隐私与解释边界

记录白名单包含 UTC 时间、会话和操作标识、应用版本/构建标识、模块、耗时、错误分类及错误码。内部代码位置与异常类型仅接受受控代码标识，未知值省略。写入和历史导出使用同一白名单，不保存用户正文、便签内容、文件名、完整路径、用户名、启动参数、原始异常消息或原始堆栈。

Windows 应用错误摘要仅采集相关应用最近七天的有限条目，读取受超时与脱敏限制。日志刷新超时、文件或事件读取失败会在包内说明；“未收集到异常”和“采集不完整”是不同状态。裁剪计数仅描述本次可读取历史中的容量省略，不能统计已经轮转淘汰或未成功落盘的异常。

记录缺失不能单独证明正常退出或崩溃。原生 fail-fast、强制结束、电源中断和磁盘故障可能没有最后记录。异常记录也不等于恢复成功；本版不保留正常开始/完成轨迹，不能据此重建每次操作全过程。退出等待传输超时记录为超时，与用户主动取消区分；退出业务行为保持不变。

## 本轮验证与用户手测

自动验证仅执行 `TuckPane.LogicChecks --stability diagnostics-limits`，覆盖异常过滤与 UTC、历史兼容与隐私、小预算裁剪及 ZIP 上限、小样本轮转与失败/取消的目标保护。使用隔离数据目录和事件读取替身；必要编译包含在本轮检查中。执行状态与证据以根目录 [PLAN.md](../PLAN.md) 为准。

以下由用户自行操作，agent 不启动应用，不执行窗口或鼠标键盘自动化：

1. 在支持应用内更新的旧客户端的设置“更新”页手动检查，确认发现正式版 4.1.0，完成下载、更新及重启。
2. 确认升级后显示 4.1.0，原有收纳关联、布局、便签/待办和真实文件仍在；无需重复测试所有旧功能。
3. 导出诊断包，确认 ZIP 可打开、包含上述三个文件，文件大小不超过 5,242,880 字节；检查 UTC 时间和采集状态说明。没有异常时允许记录文件为空。
4. 再次打开导出选择器并取消，确认没有错误提示且既有 ZIP 未改变。无需人为制造崩溃或反复触发故障。

非 GUI 自动检查通过不代表完整更新、重启或实际界面体验已通过；这些结果待用户反馈。
