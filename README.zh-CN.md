# TuckPane

[English](README.md) | [简体中文](README.zh-CN.md)

TuckPane 是一款适用于 Windows 10 22H2 与 Windows 11 x64 的桌面文件收纳工具。它把真实文件和文件夹集中到可收起的桌面窗口中，需要时展开，平时尽量少占用桌面空间。

## 应用内更新（4.0.0）

设置左侧新增“更新”。启动后每 24 小时至多检查一次 GitHub 正式版，有新版时仅显示侧栏提示，也可手动检查。点击“更新并重启”后才下载，校验成功后保存设置、便签和待办，备份配置并更新原程序目录。安装版和便携版均支持；收纳文件、窗口布局与目录关联原位保留。

配置备份位于实际配置目录的 `updates/config-backups`，例如 `%LOCALAPPDATA%\TuckPane\updates\config-backups`；旧 GlassFolder 用户继续使用旧数据根。便携版也沿用现有数据位置。程序目录不能与收纳或配置目录重叠。失败详情显示在更新页，下载失败可重试；安装后需系统重启时按提示操作。

4.0.0 汇总应用内更新及此前积累的 Dock 栏、收纳窗布局与外观、便签/待办和存储改进，具体功能见下文。自动更新专项检查已通过；实际 GUI 安装与升级行为尚未经用户手测确认。验证步骤见 [更新手测清单](docs/UPDATE_HANDTEST.zh-CN.md)。专项检查仅运行 `dotnet run --project tests/TuckPane.UpdateChecks -c Release -- --updates`。

### 快捷功能

可以直接把文件和文件夹拖入收纳窗，从显示器边缘呼出中转站，在真实文件旁创建便签和待办，按住 `Ctrl` 并滚动鼠标调整内容大小，并让 TuckPane 安静驻留在系统托盘中。

## 功能

- 普通收纳窗不设产品数量上限，可使用悬浮或桌面定位模式；还可创建贴靠屏幕边缘、呼出时不抢键盘焦点的中转站。中转站原有数量及模式转换限制保持不变。
- 普通收纳窗可单层放入任一未被收纳的根收纳窗，双方的真实保存目录都不会移动；图标模式把内部收纳窗显示为实时小窗口，精简模式则显示 TuckPane 图标与收纳窗名称。中转站始终留在根层；已被收纳的窗口、或内部已有收纳窗的窗口不能继续互嵌。
- 可在收纳目录顶层直接创建包含文字和粘贴图片的 `.tucknote` 便签，支持七种主题、正文横线、标题内联改名和窗口位置保存。
- 可创建便携 `.tucktodo` 待办，支持编辑、拖动排序、完成撤销、主题、字号缩放、标题内联改名和窗口位置保存。
- 文件、文件夹、应用快捷方式、Steam `.url` 快捷方式和便携便签可在收纳窗或标准 Windows 目标之间拖动，并协商复制、移动或创建链接。
- 普通收纳窗的图标和精简模式均可从四边和四角同比拉伸，内容面板、图标、文件名、行距与留白同步缩放，临时展开和永久展开均适用；标题保持独立大小。每种模式分别保存整体内容倍率，旧配置缺失时默认为 1。
- 单击展开窗口的可见标题可原位改名：回车或失焦提交，Esc 取消；按下标题后形成位移则拖动窗口。鼠标超过按 DPI 换算的位移阈值立即起拖，无需长按等待；触屏长按保持原样。
- 精简模式左侧到首个图标的总留白缩为之前的 2/3，包含行内留白；图标到文件名的间距不变，留白继续参与整体内容缩放。
- 收纳窗拖入另一收纳窗时，与文件拖入共用展开保护和结束清理；成功、离开、取消及失败均释放临时保护，后续展开状态遵守离开收起延迟和永久展开设置。
- 图标模式可用 `Ctrl + 滚轮` 调整图标、文件名和间距；精简模式则独立调整整行元素比例，普通滚轮仍用于滚动列表。
- 图标模式和精简模式的普通滚轮都按当前行距平滑滚动；已有和新建收纳窗的名称、标题及项目文字统一为白色。
- 设置左侧“右键菜单”独立管理窗口菜单项；“显示”页可隐藏右上角收缩标志，原位置仍可点击收缩。Dock 各类已有改名弹窗按 Dock 当前所在屏幕的工作区居中。
- Station 只在其配置显示器的对应边缘热区展开自身，不会因其他显示器底边操作显示或抬升其他收纳窗。
- 普通收纳窗可选择悬浮后展开、鼠标离开后收缩，也可设置是否只允许一个窗口保持展开。
- 支持粘贴文件、新建文件夹、通过 Windows 剪贴板剪切项目，以及把真实文件移入回收站。
- 右键可打开设置、复制空白窗口、切换模式、重命名、打开收纳目录或安全删除窗口；通用设置还可分别统一悬浮/定位模式的底部名称大小。
- 支持浅色、灰色、纯浅色、纯深色、白色磨砂和深色磨砂主题，以及 English、简体中文、日本語界面。
- 启动后只驻留系统托盘。关闭设置窗口只会隐藏；只有托盘菜单中的“退出”会结束 TuckPane。

## 存储与数据

### 右键桌面空白处创建收纳窗

右键桌面空白处，选择“新建收纳窗”；Windows 11 的经典菜单入口可能位于“显示更多选项”中。**设置 → 系统 → 桌面右键菜单** 提供独立开关，与文件夹菜单分别控制。新安装版默认开启，已有安装版升级且无桌面菜单偏好时同样开启，显式关闭的选择保留；便携版需要手动开启。自动启动、修复与卸载均尊重程序副本归属。

`--create-organizer` 命令启动或转交给单个应用实例，直接按默认名称、默认保存目录、3×3 图标布局和既有显示器放置规则创建悬浮收起窗口；不打开创建设置页，失败沿用现有提示。

### 右键文件夹创建收纳窗

4.0.0 已包含此功能。

- **安装版**：完成安装即默认启用，通常无需管理员权限。可在 **设置 → 系统 → 文件夹右键菜单** 关闭；升级保留明确关闭的选择。
- **便携版**：完整解压并运行后，在同一设置页开启一次。仅下载或解压不会自动添加菜单。
- **Windows 10**：右键一个真实文件夹，选择“使用 TuckPane 创建收纳窗”。**Windows 11**：通常先选择“显示更多选项”。桌面上的真实文件夹同样适用；空白处、多选和文件夹快捷方式不提供此入口。

无论软件尚未启动还是已驻留托盘，命令都会交给单个 TuckPane 实例处理。新窗口直接关联原目录，名称采用文件夹名，以悬浮、收起入口、3×3 图标网格创建；开启统一悬浮入口大小时采用统一尺寸。文件及原目录保持原位，不显示创建设置页。同目录重复点击会提示已有收纳窗，目录重叠、受保护或网络目录限制继续适用。普通收纳窗没有创建数量上限，加载配置也不会再截断超过原 12 个上限的窗口。

父目录和子目录不能分别关联收纳窗。创建失败时会显示独立错误弹窗，不打开总控台；目录冲突会列出所选路径、已有收纳窗名称及保存路径，点击“知道了”关闭。

窗口名称与真实目录名称独立。文件夹名只用于初始化新窗口名称；从展开标题、窗口右键或管理页改名仅更新显示名称，并在重启后保留，不会移动目录、修改文件名或改变便签与待办的保存路径。

移动便携版后，从新位置运行并点击 **修复关联**。关联到另一份程序时，显式开启或修复会切换到当前程序；普通启动不会抢占关联。删除便携版文件夹前先关闭菜单；直接删除文件不会自动清理注册表。安装版卸载仅移除仍指向本安装目录的文件夹菜单，不移除后来由便携版接管的菜单。注册失败可在设置页查看错误并重试。

失败提示的定向入口为 `--organizer-create-feedback`，名称解耦为 `--sep08-fixes organizer-rename`，均由 `TuckPane.LogicChecks` 执行且不启动窗口或修改真实注册表。实际菜单、弹窗和名称显示由用户手测，清单及验证状态见 [PLAN.md](PLAN.md)。

### 保存位置

新安装默认把收纳数据保存到 `%USERPROFILE%\TuckPane`，把设置和缓存保存到 `%LOCALAPPDATA%\TuckPane`。如果电脑上只有旧版 GlassFolder 数据，TuckPane 会原地继续使用，不复制或移动已有收纳文件。

每个新收纳窗使用一个类似 `%USERPROFILE%\TuckPane\Windows\名称-ID` 的单层目录，文件直接保存在其中。也可以选择一个已有的专用目录作为最终保存位置，该目录现有的顶层内容会立即显示。为了避免误操作无关数据，TuckPane 会拒绝范围过大或与其他收纳目录重叠的位置。

收纳窗内新建的便签就是目录顶层可见的 `.tucknote`；旧版内部便签会在启动时逐张安全迁移，单张失败不影响其他便签并会在下次启动重试。

修改全局便签主题时，已注册收纳目录顶层的有效 `.tucknote` 即使未打开也会更新；子目录和未注册目录不会被扫描。

从窗口右键或管理页删除收纳窗时，弹窗会让你选择“整个保存文件夹移到桌面”或“文件留在原路径”，也可取消；每次独立选择，不记住上次选择，也不在设置中控制。选择移到桌面时，TuckPane 只在整个保存目录成功移动后删除窗口，失败或取消时保留原目录和窗口；被删除窗口直接包含的收纳窗会自动返回桌面，它们各自的真实保存目录不会移动。如果桌面没有足够网格位置来释放其中的定位收纳窗，删除会在移动文件前停止。已打开便签会保持打开并改为保存到桌面新路径。选择留在原路径时只删除窗口，目录、文件和便签路径保持原位。卸载 TuckPane 不会删除收纳文件或设置。

## 构建

安装 .NET SDK 10.0.400 和 Inno Setup 6，然后运行：

```powershell
.\scripts\build-release.ps1
```

仅运行本次更新功能的定向自动检查：

```powershell
dotnet run --project .\tests\TuckPane.UpdateChecks -c Release -- --updates
```

检查隔离验证更新判断、下载、配置备份及便携文件替换，不启动 GUI 或真实安装器。实际安装与升级行为尚未经用户手测确认；验证与发布状态见 [PLAN.md](PLAN.md)。
